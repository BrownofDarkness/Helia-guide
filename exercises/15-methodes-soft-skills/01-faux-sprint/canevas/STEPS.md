# Étapes du sprint

## 0 — Setup (1-2 h)

- [ ] Lire `templates/dor-dod.md`, l'adapter, l'afficher dans le repo.
- [ ] Créer 8 tickets via `templates/issue.md` (canevas fourni).
- [ ] Prioriser MoSCoW.
- [ ] Estimer en T-shirt sizes.
- [ ] Définir le **sprint goal** (1 phrase mémorable).

## 1 — Sprint planning (45 min)

- [ ] Capacité connue (`templates/capacity.md`).
- [ ] Sélection des tickets.
- [ ] Owner par ticket.
- [ ] Validation en équipe.

## 2 — Sprint (J1 → J9)

- [ ] **Dailies** quotidiennes (15 min sync ou thread Slack 9h-9h30).
- [ ] **PR + revue** suivant `templates/pr-template.md` et Conventional Comments.
- [ ] **ADR** capturée sur une décision technique (`templates/adr.md`).
- [ ] **Refinement** régulier (1×/sem) pour préparer le sprint suivant.

## 3 — Fin de sprint (J10)

- [ ] **Sprint review** : démo + Q&A (`templates/review-agenda.md`).
- [ ] **Rétrospective** : Start / Stop / Continue + 2 actions (`templates/retro.md`).
- [ ] **Post-mortem** sur incident fictif (`templates/post-mortem.md`).

## 4 — Rapport

- [ ] `SPRINT_REPORT.md` (modèle dans `templates/`).

Voir `correction/` pour des exemples complets.
