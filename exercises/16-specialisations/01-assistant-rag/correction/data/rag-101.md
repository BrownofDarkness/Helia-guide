# RAG 101 — Concepts essentiels

## Qu'est-ce que le RAG

RAG signifie *Retrieval-Augmented Generation*. Au lieu de fine-tuner un LLM sur tes données privées, tu **récupères** à chaque question les morceaux pertinents de ton contenu et tu les injectes dans le prompt.

## Pipeline d'ingestion

1. Lister les documents.
2. Chunker en morceaux de 500 à 1500 tokens.
3. Calculer les embeddings.
4. Stocker dans une vector DB (pgvector, Qdrant, Pinecone…).

## Pipeline de réponse

1. Embedder la question utilisateur.
2. Recherche top-K dans la vector DB.
3. Composer un prompt système strict avec le contexte.
4. Streamer la réponse via le LLM.

## Recherche hybride

La recherche purement vectorielle rate les requêtes très précises (noms propres, codes produit). Combiner avec BM25 (full-text) puis fusionner via Reciprocal Rank Fusion (RRF) améliore la précision de 15-30%.

## Citations forcées

Le system prompt doit imposer la citation des sources sous un format normalisé. Sans citations, l'utilisateur ne peut pas vérifier — et les hallucinations passent inaperçues.

## Anti-hallucinations

- System prompt strict : "Si l'info n'est pas dans le contexte, dis 'je ne sais pas'".
- Citation des sources obligatoire.
- Évaluations sur un golden set de questions pièges.
- Hybrid search pour ne pas rater les détails précis.
